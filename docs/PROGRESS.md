### ⚠️ Blocker: Docker engine cannot start on this machine

```
$ docker ps
request returned 500 Internal Server Error for API route and version
http://%2F%2F.%2Fpipe%2FdockerDesktopLinuxEngine/v1.55/containers/json

$ wsl --status
WSL2 is unable to start since virtualization is not enabled on this machine.
Please ensure the "Virtual Machine Platform" optional component is enabled and
virtualization is turned on in your computer's firmware settings.
```

Hardware virtualization is disabled in firmware, so the WSL2 backend that Docker Desktop needs cannot
start. Enabling it requires a BIOS/UEFI change plus an elevated `wsl.exe --install --no-distribution`
and a reboot — outside what can be done from this session.

**Consequences and mitigations**

- `Dockerfile` and `docker-compose.yml` are still authored and committed as required deliverables. They
  are reviewed by eye and by CI (the GitHub Actions runner has a working Docker engine and builds the
  image), but they were **not executed on this machine**.
- **Testcontainers cannot be used.** Per §3 of the brief, the `test` profile points at a real local
  MySQL 8 instead — never H2. See [ADR-0002](DECISIONS.md#adr-0002--integration-tests-run-against-a-local-mysql-84-instance-not-testcontainers).
- A dedicated MySQL 8.4.9 instance was started on **port 3307** from the already-installed server
  binaries, with its own data directory, so the developer's existing `MySQL84` service on 3306 is
  untouched. See [`database/README.md`](../database/README.md).
